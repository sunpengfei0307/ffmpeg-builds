# `-report` 写日志文件

把本次进程的命令行和 `av_log` 打到独立文件。每次启动一个新文件，不覆盖上一次。

## 变更记录

| 日期 | 说明 |
|------|------|
| 2026-09-02 | `-report` 可带前缀：生成 `前缀-YYYYMMDD-HHMMSS.log`；不带参数仍为当前目录 `ffmpeg-时间.log` |

## 用法

| 命令 | 生成文件 |
|------|----------|
| `-report` | `./ffmpeg-20260902-150906.log`（与上游相同） |
| `-report /data/LCMS/log/27060_test_rtmp_h264_1080p` | `/data/LCMS/log/27060_test_rtmp_h264_1080p-20260902-150906.log` |

时间用本地时区，格式 `YYYYMMDD-HHMMSS`。重启进程会再开一个带新时间戳的文件。

```bash
./ffmpeg \
  -report /data/LCMS/log/27060_test_rtmp_h264_1080p \
  -i ... \
  ...
```

启动后控制台会有一行 `Report written to "..."`，确认实际路径。

前缀末尾若带 `.log` 会去掉再拼时间，避免 `foo.log-20260902-150906.log`。

## 与 `FFREPORT` 的关系

环境变量 `FFREPORT=file=模板:level=数字` 仍可用（`%p`=程序名，`%t`=时间）。同时写 `-report 前缀` 时，**以前缀文件名为准**，`level=` 仍生效。

## 注意事项

- 父目录必须已存在，本选项不自动 `mkdir`
- `-report` 尽量放在命令最前，才能把早期日志也写入文件
- 下一个参数若以 `-` 开头，视为选项而不是前缀（无参数的 `-report`）
- 不要把前缀写成目录（以 `/` 结尾会得到 `.../-20260902-150906.log`）

## 踩坑

| 现象 | 处理 |
|------|------|
| `Failed to open report` | 目录不存在或无写权限 |
| 前缀被当成输入文件 | 旧二进制不认 `-report` 参数；需带本次改动的进程 |
| 只有 `ffmpeg-*.log` 在当前目录 | 没传前缀，或前缀被下一选项吃掉（前缀不要以 `-` 开头） |
